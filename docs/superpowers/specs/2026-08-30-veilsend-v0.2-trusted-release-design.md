# VeilSend v0.2 可信发布版设计规格

- 状态：待规格审查
- 目标版本：`0.2.0-beta.1`
- 目标平台：Windows 10/11 x64
- 日期：2026-08-30

## 1. 摘要

VeilSend v0.2 的主题是“可信发布”，不是继续扩大脱敏检测范围。当前版本已经具备文本、图片和 PDF 的本地脱敏闭环；v0.2 要把这些能力交付为普通 Windows 用户可以安装、验证、离线运行和卸载的公开测试版，并让用户能确认自己正在运行哪个构建、检测链是否完整，以及输出是如何被验证的。

本版本继续坚持以下产品边界：扫描和保存期间不上传文件、不使用账户、不发送遥测、不依赖云端模型、不覆盖原文件。与需要 GPU、模型服务或多进程后端的重型脱敏系统相比，VeilSend 继续定位为轻量、单机、低门槛的分享前安全检查工具。

## 2. 背景与问题

v0.1 已建立三条主要安全链：

1. 文本：检测、编辑、复扫、复制。
2. 图片：元数据清理、OCR/二维码/人脸等检测、遮盖、导出后复验。
3. PDF：逐页检测、遮盖、导出后复验。

但目前仓库仍更接近“可测试的源码”，还不是可信的桌面软件发布：

- Tauri 安装包未作为稳定交付物启用。
- 没有可重复的 GitHub Actions 发布流水线。
- 没有公开校验和、SBOM 和构建来源证明。
- 应用内缺少构建身份、检测器状态和隐私安全诊断信息。
- 图片/PDF 的单文件导入和 PDF 长文档浏览仍有明显操作摩擦。
- 版本号、标签、安装包和发布说明还没有强制一致性检查。

v0.2 要优先解决这些信任与交付问题。在此之前增加 Office、批量目录或大模型能力，会扩大攻击面和维护面，却不能回答用户最基础的问题：“我下载的是否是官方构建，它是否真的在本地完整运行？”

## 3. 目标

### 3.1 用户目标

- 非开发者可以在 Windows 10/11 x64 上安装、启动、离线使用和卸载 VeilSend。
- 用户可以从官方 GitHub Release 下载标准安装包或便携包。
- 用户可以用 SHA-256 校验下载文件，并查看构建物料清单和来源证明。
- 用户可以在应用内看到准确的版本、提交、发布通道与检测器可用状态。
- 用户可以复制不含原始敏感内容的诊断报告和验证回执。
- 用户可以把单个图片或 PDF 拖入对应工作区，并高效浏览多页 PDF。

### 3.2 工程目标

- 每次进入主分支的变更都经过前端、Rust、格式、静态检查和依赖安全检查。
- 每个版本标签都经过版本一致性检查，并只产生一组可追溯的 Windows x64 构建物。
- 发布资产先进入草稿预发布，只有通过干净 Windows 环境验收后才能公开。
- CI、安装器和应用运行时均遵守最小权限原则。
- 所有现有安全不变量继续成立：不覆盖源文件、失败时不生成误导性安全输出、导出后重新验证。

### 3.3 成功标准

- 公开 `v0.2.0-beta.1` GitHub 预发布包含安装包、便携包、校验和、SBOM、来源证明和发布说明。
- 在一台未安装开发工具的 Windows 10/11 x64 测试环境完成安装、三种文件流程、断网运行和卸载验收。
- 自动化测试覆盖版本同步、诊断隐私、拖放校验和 PDF 坐标不变性。
- 发布页面对未签名测试版或已签名构建的状态进行准确披露，不制造“已签名”假象。

## 4. 非目标

v0.2 明确不包含：

- DOCX、XLSX、PPTX 或其他 Office 格式。
- 文件夹扫描、批量任务、任务队列或多文件并行处理。
- LLM、VLM、远程 NER 服务或可下载模型。
- 账户、云同步、在线协作、遥测或崩溃自动上传。
- macOS、Linux、ARM64 或 Windows 7/8 支持。
- 后台自动更新、静默更新或启动时自动联网检查。
- 文件关联、右键菜单、开机启动或后台服务。
- 最近文件列表、源文件缓存或会话自动恢复。
- 覆盖原文件或原路径就地保存。
- 在代码签名准备完成前宣称稳定版。

## 5. 发布身份与通道

### 5.1 版本身份

首个 v0.2 构建采用：

- 应用版本：`0.2.0-beta.1`
- Git 标签：`v0.2.0-beta.1`
- GitHub Release：Pre-release
- 产品名：VeilSend
- 平台标识：Windows x64

`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 中的版本必须保持一致；发布工作流在构建前比较三处版本与标签，任意不一致立即失败。

### 5.2 交付资产

正式预发布至少包含：

- `VeilSend_0.2.0-beta.1_x64-setup.exe`：NSIS 当前用户安装器。
- `VeilSend_0.2.0-beta.1_x64-portable.zip`：便携包。
- `SHA256SUMS.txt`：所有用户可下载资产的 SHA-256。
- `veilsend-0.2.0-beta.1-sbom.cdx.json`：CycloneDX SBOM。
- GitHub artifact attestation：构建来源证明。
- `RELEASE_NOTES.md` 内容对应的 GitHub 发布说明。

所有资产由 CI 从标签对应提交构建。官方 Release 不接受维护者本地机器手工上传的二进制，以避免同一版本存在不可追溯的不同构建。

### 5.3 签名政策

- 测试版允许在代码签名证书尚未到位时发布，但文件名附近和发布说明首屏必须明确标记“未签名测试版”，并说明 Windows 可能显示 SmartScreen 提示。
- 应用不得伪装签名状态，也不得指导用户关闭系统安全功能。
- 正式稳定版是硬门槛：没有有效 Authenticode 签名不得移除 beta 标识。
- 签名证书、密码或令牌只进入受保护的发布作业，不提供给拉取请求作业，不写入日志或构建资产。

## 6. 总体架构

```text
源码与锁文件
    │
    ├── pull request / push ──> CI 质量门禁
    │                              ├── 前端测试与构建
    │                              ├── Rust 格式/静态检查/测试
    │                              └── 依赖安全检查
    │
    └── v* 标签 ─────────────> 发布工作流
                                   ├── 版本/标签一致性
                                   ├── Windows x64 可重复构建
                                   ├── NSIS + portable
                                   ├── SHA-256 + SBOM + attestation
                                   └── 草稿预发布
                                             │
                                      干净系统人工验收
                                             │
                                      手动公开预发布
```

应用内部不引入新的网络层或后台进程。v0.2 只增加少量本地边界组件：

```text
现有文本/图片/PDF 工作流
    ├── BuildInfo：编译期版本、提交和发布通道
    ├── DetectorStatus：检测器可用性与完成状态
    ├── SafeDiagnostics：显式生成的隐私安全诊断文本
    ├── VerificationReceipt：显式生成的输出验证回执
    ├── DropBridge：把单文件拖放交给现有 Rust 会话校验
    └── PdfViewState：仅影响显示的缩放和键盘翻页状态
```

拖放不能绕过 Rust 层的文件类型、大小、页数或状态校验；PDF 缩放不能改变现有归一化遮盖坐标。BuildInfo 与诊断接口只返回预先定义的非内容字段。

## 7. CI 质量门禁

新增 `.github/workflows/ci.yml`，在拉取请求和主分支推送时运行。工作流使用只读默认权限，不向来自分叉仓库的代码暴露任何秘密。

### 7.1 前端门禁

- 使用锁文件安装依赖：`npm ci`。
- 运行现有前端测试。
- 运行 TypeScript/前端生产构建。
- 对新增的版本同步、诊断字段、拖放状态和 PDF 视图状态进行测试。
- 依赖审计发现高危或严重漏洞时失败；中低风险生成可跟踪报告，不在没有评估的情况下自动忽略。

### 7.2 Rust 门禁

- `cargo fmt --all -- --check`。
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`。
- `cargo test --workspace --all-features`。
- RustSec 审计发现可利用的已知漏洞时失败；仅维护状态警告必须记录并单独评估。

### 7.3 Windows 能力相关测试

Windows OCR、人脸或系统运行时能力可能随 GitHub 托管 runner 镜像变化，不能把“runner 缺能力”伪装成检测通过。因此测试分为两层：

- 托管 CI：运行纯逻辑、解析、坐标、状态机、隐私字段和使用模拟检测结果的测试。
- 发布验收：在维护者控制的干净 Windows 10/11 x64 环境运行真实文本、图片、PDF 合成夹具，核验所有声明支持的检测器确实可用并完成。

如果真实能力验收缺失或某个必需检测器不可用，Release 必须保持草稿，应用状态必须显示“需要检查”，不能显示“已验证”。

### 7.4 工作流安全

- 第三方 GitHub Action 固定到完整提交 SHA，并在注释中注明上游版本。
- 工作流权限按作业收窄；普通 CI 不授予 `contents: write`、`id-token: write`。
- 发布作业才获得创建 Release 和生成 attestation 所需的权限。
- 拉取请求代码不运行签名步骤，不读取发布秘密。
- 依赖缓存键包含锁文件哈希，不缓存构建后的用户数据或测试输出内容。

## 8. 发布流水线

新增 `.github/workflows/release.yml`，只响应符合 `v*` 的标签，并执行以下阶段：

1. 校验标签语义版本与三处应用版本完全一致。
2. 在干净 Windows runner 通过与主 CI 相同的质量门禁。
3. 使用锁定依赖构建 Windows x64 Tauri 应用。
4. 生成当前用户 NSIS 安装器和便携 ZIP。
5. 生成 SHA-256、CycloneDX SBOM、第三方许可清单和 artifact attestation。
6. 检查交付资产列表、命名和校验和是否完整。
7. 创建或更新“草稿 + 预发布”Release，不直接公开。
8. 维护者完成干净系统验收并记录结果后，手动公开该预发布。

流水线采用原子发布原则：失败时不留下已公开的部分资产；重跑同一标签只能更新仍处于草稿状态的 Release，已经公开的标签不可静默替换二进制。公开资产如需修复，必须发布新的预发布版本号。

## 9. Windows 打包设计

### 9.1 NSIS 安装器

- 默认按当前用户安装，不要求管理员权限。
- 创建开始菜单快捷方式和标准卸载入口。
- 不创建开机启动、后台服务、计划任务、文件关联或浏览器扩展。
- 卸载仅移除程序文件和明确属于 VeilSend 的应用配置，不触碰用户源文件或导出文件。
- 安装器清晰显示应用名、版本、发布者签名状态和目标目录。

### 9.2 便携包

- ZIP 内包含主程序、运行所需文件、简短启动说明、许可证与第三方许可说明。
- 解压后无需安装和管理员权限即可启动。
- 不把源文件、预览或诊断信息写入程序目录作为持久历史。

### 9.3 WebView2 与离线边界

Windows 10/11 的 WebView2 运行时作为系统前置能力处理；标准安装器可使用 Microsoft 官方运行时引导机制。发布说明必须披露这一安装依赖。

“本地优先”在 v0.2 的承诺是：应用安装完成后，扫描、遮盖、复验和保存均可断网运行。它不等于安装器必须携带完整离线 WebView2 运行时。应用启动后不会因为断网而降低检测能力，也不会自动联网检查更新。

## 10. 应用内信任信息

### 10.1 关于面板

关于面板显示：

- VeilSend 版本与发布通道。
- 构建提交的短哈希和构建目标。
- 许可证。
- “文件不会上传；扫描和保存均在本机完成”的边界声明。
- 当前设备上的检测器可用状态，不显示或保存检测到的内容。
- GitHub Releases、源代码和安全报告入口；只有用户点击时才调用系统浏览器打开，不做后台请求。

编译期无法获得提交身份时，构建必须明确显示 `unverified build`，官方发布流水线则把提交身份作为必填项。

### 10.2 隐私安全诊断报告

诊断报告只在用户点击“复制诊断信息”后生成并放入剪贴板，应用不自动保存或上传。允许字段包括：

- 应用版本、通道、构建提交、目标架构。
- Windows 版本和架构。
- 输入类别（文本/图片/PDF），不含文件名和路径。
- 检测器的可用/已完成/失败状态。
- 高层错误代码、配置的大小或页数限制、当前工作流状态。
- 输入大小区间和 PDF 页数；大小使用区间而不是精确字节数。

禁止字段包括：

- 文件名、目录、完整路径、最近文件记录。
- 原文、OCR 文本、脱敏预览、用户自定义词和剪贴板原内容。
- 二维码/条形码载荷、EXIF 内容、人脸坐标或手工遮盖坐标。
- 源文件字节、导出文件字节、临时文件位置。
- 默认情况下的源文件或输出文件哈希。

测试必须采用“允许列表 + 敏感哨兵负向断言”：未在允许列表中的字段不能进入报告，夹具中的敏感哨兵字符串不能出现在诊断快照中。

### 10.3 验证回执

用户可在成功导出后复制纯文本验证回执。默认包含：

- 应用版本和构建提交。
- 输出类型、验证状态、页数或图像尺寸。
- 各检测器是否完成、发现数量与剩余未解决异常数量。
- 导出时间、输出大小区间。

默认不包含源文件信息、内容片段或哈希。界面可提供“包含输出 SHA-256”复选项，默认关闭，并明确说明哈希可以用于确认文件一致性但也可能成为可关联标识。只有最终已保存的输出可计算该可选哈希。

## 11. 单文件拖放

图片和 PDF 工作区支持拖入一个文件，文本工作区保持现有输入方式。

- 拖动悬停时只显示视觉反馈，不读取文件内容。
- 放下后把原始路径交给现有 Rust 会话入口，由 Rust 统一执行路径、文件类型、大小、页数和状态校验。
- 目录、多文件、空拖放、不支持扩展名、伪造扩展名和超限文件均被拒绝，并显示不泄露路径的可操作错误。
- 扫描、导出或复验进行中禁用替换源文件。
- 在空闲状态替换文件时，先通过会话清理流程释放现有预览和临时资源，再载入新文件。
- 拖放不增加文件持久记录，也不能绕过“不覆盖源文件”的保存规则。
- 键盘和按钮选择文件仍然完整可用，拖放不是唯一入口。

## 12. PDF 缩放与键盘导航

v0.2 只改善显示和导航，不改变 PDF 处理模型：

- 缩放范围为 50%–200%，步进 25%。
- 提供“适合宽度”和“适合页面”两种快捷状态。
- 缩放只影响视图变换；手工遮盖继续以页面归一化坐标保存，缩放前后导出位置必须一致。
- `PageUp`/`PageDown` 在焦点不位于输入控件时切换页面。
- `+`/`-` 在焦点不位于输入控件时调整缩放。
- `Esc` 取消正在绘制但尚未提交的遮盖框，不删除已提交遮盖。
- 所有按钮有可访问名称、可见焦点和禁用状态。
- 视图状态只存在于当前会话；关闭应用后不恢复文档或页码。

本版本不加入页面重排、合并文档、缩略图批量选择或多文档标签页。

## 13. 失败与安全状态

- 任一 CI 或发布步骤失败时，不产生公开 Release。
- 版本、标签或资产清单不一致时停止发布。
- 必需检测器不可用、未运行或复验失败时，应用保持“需要检查”，禁止给出“已验证”状态。
- 拖放、诊断或关于面板故障不能破坏现有扫描会话，也不能泄露源路径。
- 安装、升级和卸载不删除或覆盖用户源文件及导出文件。
- 应用崩溃恢复不自动重新打开上次源文件。
- 诊断复制失败时只提示复制失败，不把报告写入临时明文文件作为后备。
- 导出仍使用新路径和现有安全保存流程；输出冲突必须由用户显式选择新名称，不做静默覆盖。

## 14. 供应链与安全控制

- GitHub Release 是唯一官方二进制发布渠道。
- npm 与 Cargo 锁文件纳入版本控制并用于 CI。
- 第三方 Action 固定完整 SHA，定期由依赖更新工具提出审查变更。
- 普通 CI 最小权限且无秘密；发布作业权限与秘密隔离。
- 每个 Release 提供 SHA-256、SBOM 和 GitHub artifact attestation。
- 正式版必须完成 Authenticode 签名；beta 的未签名状态必须披露。
- 应用 Content Security Policy 继续禁止非必要网络目标。
- v0.2 不加入 updater、HTTP 客户端、分析 SDK 或崩溃上报 SDK。
- 安全问题通过仓库安全政策和 GitHub 私密漏洞报告渠道接收，不要求用户公开敏感样本。

## 15. 文档与社区交付

v0.2 同步补齐：

- `README.md`：下载入口、安装/便携运行、离线边界、校验方法、测试版签名提示。
- `CHANGELOG.md`：v0.2 变更、兼容性和已知限制。
- `docs/release.md`：维护者发布、签名、草稿验收和撤回流程。
- `SECURITY.md`：支持版本、私密报告方式、禁止上传真实敏感样本的提醒。
- `CONTRIBUTING.md`：本地门禁、合成夹具要求、隐私测试原则。
- GitHub issue 模板：缺陷、功能建议；安全模板明确引导到私密渠道。
- Release Notes：功能、安装、资产验证、未签名状态、已知限制和回滚方式。

所有演示和测试文件必须是合成夹具，不把真实身份证、联系方式、内部文档或用户文件提交到仓库和 CI 资产。

## 16. 测试设计

### 16.1 自动化测试

- 版本同步：三处版本和模拟标签一致/不一致案例。
- BuildInfo：官方构建与缺提交身份构建的显示状态。
- 诊断允许列表：每个允许字段的序列化与敏感哨兵负向断言。
- 验证回执：默认无哈希、显式选择后只包含最终输出 SHA-256。
- 拖放：单文件成功、目录、多文件、忙碌状态、不支持类型、伪造扩展名、超限输入。
- 会话替换：旧预览和临时资源被清理，失败时不进入半载入状态。
- PDF 缩放：不同缩放和适配模式下归一化遮盖坐标及导出坐标不变。
- 键盘导航：焦点保护、边界页、缩放边界和取消草稿遮盖。
- 打包配置：bundle 启用、NSIS 当前用户模式、无自动启动和无额外协议注册。
- 工作流静态检查：YAML/Action 配置有效、权限和标签规则符合约束。
- 现有文本、图片、PDF Rust 与前端回归测试全部通过。

### 16.2 干净 Windows 验收

每个候选预发布在公开前完成并记录：

1. 从草稿 Release 下载资产并核对 SHA-256 与 attestation。
2. 在无 Node、Rust 或源码环境的 Windows 10/11 x64 当前用户账户安装并启动。
3. 在未授予管理员权限的情况下完成安装和卸载。
4. 启动便携包并确认不会写入持久源文件历史。
5. 安装完成后断开网络，完成文本、图片和 PDF 合成夹具的扫描、遮盖、导出和复验。
6. 核对测试前后源文件哈希不变，源目录无 VeilSend 临时残留。
7. 核对关于面板版本、提交、通道、架构和检测器状态正确。
8. 复制诊断报告，确认不含夹具文件名、路径、内容、OCR 文本、自定义词和载荷。
9. 测试拖入目录、多文件、错误扩展名、超限文件和损坏 PDF，确认安全失败。
10. 测试 PDF 缩放、键盘翻页和手工遮盖位置一致性。
11. 核对 SmartScreen/签名显示与发布说明一致。
12. 卸载后确认用户导出文件仍然存在，程序文件和应用快捷方式已移除。

验收记录只保存版本、机器环境、步骤结果和非敏感错误代码，不保存真实输入或扫描内容。

## 19. 已确定的取舍

- 先做好可信分发，再扩大格式和检测能力。
- GitHub Releases 是 v0.2 唯一官方渠道。
- Windows x64 是唯一发布目标。
- v0.2 不加入自动更新；用户只能从关于面板主动打开 Releases 页面。
- v0.2 不加入遥测、崩溃上传或任何后台联网。
- beta 可以在准确披露后暂时未签名，稳定版不能未签名。
- 真实 Windows 检测能力采用受控环境发布验收，不把托管 runner 的偶然系统能力当成安全证明。
- 诊断采用严格允许列表，输出哈希默认关闭。
- PDF 缩放只改变视图，不能改变脱敏坐标或导出结果。

## 20. 完成定义

只有满足以下全部条件，v0.2 才算完成：

- E1–E4 的代码、测试和文档进入主分支，全部 CI 门禁通过。
- 标签、版本、安装包元数据和关于面板显示完全一致。
- 草稿 Release 资产完整，校验和、SBOM 和 attestation 可验证。
- 干净 Windows 10/11 x64 验收全部通过且有非敏感记录。
- 安装后断网时三种现有工作流均可完成安全闭环。
- 诊断、回执、日志和构建资产中没有合成敏感哨兵泄漏。
- 已知限制、签名状态和 WebView2 依赖在发布说明中准确披露。
- 没有会导致源文件修改、误报“已验证”或公开不完整资产的阻断问题。
- `v0.2.0-beta.1` 以 GitHub Pre-release 公开；在代码签名和 beta 反馈门槛完成前不标记为稳定版。
