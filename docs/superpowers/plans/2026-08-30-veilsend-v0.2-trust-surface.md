# VeilSend v0.2 Trust Surface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the installed app identify its build and detector capabilities, provide an allowlisted privacy-safe diagnostic report, and issue copyable verification receipts for saved outputs.

**Architecture:** Rust owns compile-time build identity, Windows capability probes, and saved-file fingerprints. TypeScript receives only bounded serializable values, formats diagnostics and receipts from closed unions, and renders one trust-center dialog plus one reusable receipt component; arbitrary source content, paths, payloads, and errors never enter either report.

**Tech Stack:** Rust 2024, Tauri 2 commands, Windows Runtime capability probes, React 19, TypeScript 5.9, Vitest 4, Tauri opener plugin.

**Spec:** `docs/superpowers/specs/2026-08-30-veilsend-v0.2-trusted-release-design.md`

## Global Constraints

- Build identity is version `0.2.0-beta.1`, channel `beta`, Windows x64; only CI-provided 40-character Git SHA yields `verifiedBuild: true`.
- A missing/invalid build SHA is displayed as `unverified build`; it is never replaced with a fabricated hash.
- About links open only after a user click and are scoped to exact `https://github.com/YuLeo926/veilsend` URLs.
- Diagnostics are generated only after a user click, copied only to the clipboard, never saved or uploaded by VeilSend.
- Diagnostics must not contain file names, paths, source text, OCR text, previews, custom terms, code payloads, geometry, bytes, or hashes.
- Verification receipts contain saved-output facts only; output SHA-256 is available only after save, default-hidden, and included only after explicit opt-in.
- Detector unavailable/failed/not-run states cannot be formatted as complete or `Verified`.
- No telemetry, updater, HTTP client, crash reporter, automatic link check, or persisted recent-file state is introduced.

#[cfg(target_os = "windows")]
fn windows_version() -> String {
    use windows::System::Profile::AnalyticsInfo;
    let value = AnalyticsInfo::VersionInfo()
        .and_then(|info| info.DeviceFamilyVersion())
        .ok()
        .and_then(|value| value.to_string_lossy().parse::<u64>().ok());
    value.map(|value| format!(
        "{}.{}.{}.{}",
        (value >> 48) & 0xffff,
        (value >> 32) & 0xffff,
        (value >> 16) & 0xffff,
        value & 0xffff,
    )).unwrap_or_else(|| "unknown".to_owned())
}

#[cfg(not(target_os = "windows"))]
fn windows_version() -> String { "not-windows".to_owned() }

- [ ] **Step 3: Implement the closed model and manual formatter**

```ts
export type DiagnosticDetectorState = "available" | "complete" | "unavailable" | "failed" | "notRun" | "notApplicable";
export type DiagnosticErrorCode = "none" | "inputRejected" | "detectorIncomplete" | "saveFailed" | "verificationFailed" | "workflowFailed";
export interface WorkflowDiagnostics {
  inputKind: "text" | "image" | "pdf";
  workflowState: "add" | "review" | "result";
  inputSizeBucket: "none" | "under 1 MiB" | "1-10 MiB" | "10-50 MiB" | "over limit";
  pageCount: number | null;
  lastErrorCode: DiagnosticErrorCode;
  detectors: Record<"text" | "metadata" | "face" | "qr" | "barcode" | "pdf", DiagnosticDetectorState>;
}

export function formatDiagnostics(runtime: RuntimeInfo, workflow: WorkflowDiagnostics): string {
  const d = workflow.detectors;
  return [
    "VeilSend privacy-safe diagnostics",
    `app_version=${runtime.appVersion}`,
    `channel=${runtime.channel}`,
    `commit=${runtime.commit}`,
    `verified_build=${runtime.verifiedBuild}`,
    `target=${runtime.target}`,
    `os_version=${runtime.osVersion}`,
    `input_kind=${workflow.inputKind}`,
    `workflow_state=${workflow.workflowState}`,
    `input_size=${workflow.inputSizeBucket}`,
    `pages=${workflow.pageCount ?? "not-applicable"}`,
    `last_error=${workflow.lastErrorCode}`,
    ...Object.entries(d).map(([name, state]) => `detector_${name}=${state}`),
  ].join("\n");
}
```

Use small exported helpers to bucket byte counts and derive detector completion from the existing session/result fields. Components send only `WorkflowDiagnostics`; root error handling stores a `DiagnosticErrorCode` separately from the human-readable error. In `TrustCenter`, the `Copy diagnostics` button calls `navigator.clipboard.writeText(formatDiagnostics(...))` only inside its click handler and confirms success without persisting the string.

```ts
export interface VerificationReceiptData {
  appVersion: string;
  commit: string;
  outputKind: "text" | "image" | "pdf";
  status: VerificationStatus;
  savedBytes: number;
  pages: number | null;
  findingsRedacted: number;
  exceptions: number;
  remainingFindings: number;
  detectors: Partial<Record<"text" | "metadata" | "face" | "qr" | "barcode" | "pdf", "complete" | "incomplete" | "notApplicable">>;
  outputFingerprint: string;
}

export function formatVerificationReceipt(data: VerificationReceiptData, includeFingerprint = false) {
  const lines = [
    "VeilSend verification receipt",
    `app_version=${data.appVersion}`,
    `commit=${data.commit}`,
    `output_kind=${data.outputKind}`,
    `status=${data.status}`,
    `saved_bytes=${data.savedBytes}`,
    `pages=${data.pages ?? "not-applicable"}`,
    `findings_redacted=${data.findingsRedacted}`,
    `exceptions=${data.exceptions}`,
    `remaining_findings=${data.remainingFindings}`,
    ...Object.entries(data.detectors).map(([name, state]) => `detector_${name}=${state}`),
  ];
  if (includeFingerprint) lines.push(`output_sha256=${data.outputFingerprint}`);
  return lines.join("\n");
}
```

`VerificationReceipt` owns an unchecked `Include output SHA-256` checkbox and a `Copy verification receipt` button. The checkbox copy explains correlation risk. Copy occurs only from the button handler; reset the checkbox when `data.outputFingerprint` changes.

Build exact adapters for text, image, and PDF result types. For text, render the component only after `SavedTextFile` exists. For image/PDF, render after their existing save-and-verify command returns. A missing/incomplete detector maps to `incomplete`, never `complete`.

- Output hashes originate only after final destination reread and never appear in diagnostics or an automatic clipboard action.
- External navigation is limited to three exact GitHub URLs and requires a user click.
- Local/unverified builds remain visibly unverified even if a Git checkout happens to contain a commit hash.
