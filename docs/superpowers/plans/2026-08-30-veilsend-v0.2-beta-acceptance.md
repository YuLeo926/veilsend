# VeilSend v0.2 Beta Acceptance and Publication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish public documentation and community safety rails, verify draft assets and all local workflows on Windows, then publish `v0.2.0-beta.1` without weakening VeilSend's privacy claims.

**Architecture:** Repository contracts check that public documentation contains the same boundaries as the app and design. A read-only PowerShell verifier checks downloaded draft assets, checksums, ZIP contents, SBOM, provenance, and declared unsigned state; controlled Windows acceptance exercises synthetic text/image/PDF paths before a maintainer converts the existing draft into a public pre-release.

**Tech Stack:** Markdown, GitHub issue forms, Node.js 24 contract tests, PowerShell 7, GitHub CLI, Windows 10/11 x64, existing Rust synthetic fixtures and Tauri package.

**Spec:** `docs/superpowers/specs/2026-08-30-veilsend-v0.2-trusted-release-design.md`

## Global Constraints

- Public version/tag is exactly `0.2.0-beta.1` / `v0.2.0-beta.1`; it remains a GitHub Pre-release.
- Beta assets are unsigned and say `UNSIGNED`; documentation describes SmartScreen accurately and never tells users to disable Windows security.
- Public claims are limited to supported text/image/PDF checks; VeilSend never promises universal safety, compliance, or perfect detection.
- Reports, issues, fixtures, acceptance records, logs, screenshots, and assets use synthetic data only and contain no user path, real secret, personal data, source content, OCR text, QR/barcode payload, or face crop.
- Standard and portable packages must run without Node, Rust, source checkout, administrator privileges, accounts, cloud services, or network access after installation.
- Publication is blocked by missing/failed detector capability, failed saved-file verification, asset/checksum/SBOM/provenance mismatch, or inaccurate signing disclosure.
- Existing source files and all user-created outputs survive install/uninstall; tests never overwrite inputs.
- Stable status is out of scope and remains blocked until valid Authenticode signing and beta feedback gates are complete.

- [ ] **Step 2: Implement exact-name, checksum, ZIP, SBOM, signature, and attestation checks**

```powershell
param(
  [Parameter(Mandatory=$true)][string]$AssetsDirectory,
  [Parameter(Mandatory=$true)][ValidatePattern('^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$')][string]$Repository,
  [switch]$SkipAttestation
)
$ErrorActionPreference = 'Stop'
if ($SkipAttestation -and $env:CI -eq 'true') { throw 'Attestation checks cannot be skipped in CI.' }
$root = (Resolve-Path -LiteralPath $AssetsDirectory).Path
$expected = @(
  'VeilSend_0.2.0-beta.1_x64-setup-UNSIGNED.exe',
  'VeilSend_0.2.0-beta.1_x64-portable-UNSIGNED.zip',
  'veilsend-0.2.0-beta.1-sbom.cdx.json',
  'SHA256SUMS.txt'
)
foreach ($name in $expected) {
  if (-not (Test-Path -LiteralPath (Join-Path $root $name) -PathType Leaf)) {
    throw "Missing expected release asset: $name"
  }
}
$unexpected = @(Get-ChildItem -LiteralPath $root -File | Where-Object Name -notin $expected)
if ($unexpected.Count) { throw "Unexpected release assets: $($unexpected.Name -join ', ')" }

$sumLines = Get-Content -LiteralPath (Join-Path $root 'SHA256SUMS.txt')
foreach ($asset in $expected | Where-Object { $_ -ne 'SHA256SUMS.txt' }) {
  $line = @($sumLines | Where-Object { $_ -match "  $([regex]::Escape($asset))$" })
  if ($line.Count -ne 1) { throw "Expected one checksum for $asset" }
  $declared = ($line[0] -split '  ', 2)[0].ToLowerInvariant()
  $actual = (Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $root $asset)).Hash.ToLowerInvariant()
  if ($declared -ne $actual) { throw "Checksum mismatch for $asset" }
}

$installer = Join-Path $root $expected[0]
if ((Get-AuthenticodeSignature -LiteralPath $installer).Status -ne 'NotSigned') {
  throw 'Beta installer signature state does not match the UNSIGNED asset contract.'
}
$sbom = Get-Content -Raw -LiteralPath (Join-Path $root $expected[2]) | ConvertFrom-Json
if ($sbom.bomFormat -ne 'CycloneDX') { throw 'SBOM is not CycloneDX.' }

$extract = Join-Path $root '.veilsend-portable-inspection-v0.2.0-beta.1'
if (Test-Path -LiteralPath $extract) { throw 'Portable inspection directory already exists; choose a clean asset directory.' }
Expand-Archive -LiteralPath (Join-Path $root $expected[1]) -DestinationPath $extract
try {
  $zipNames = @(Get-ChildItem -LiteralPath $extract -File | Sort-Object Name | Select-Object -ExpandProperty Name)
  if (($zipNames -join ',') -ne 'LICENSE,RELEASE_NOTES.md,THIRD_PARTY_LICENSES.md,VeilSend.exe') { throw "Unexpected portable contents: $($zipNames -join ', ')" }
  if ((Get-AuthenticodeSignature -LiteralPath (Join-Path $extract 'VeilSend.exe')).Status -ne 'NotSigned') {
    throw 'Portable executable signature state does not match the UNSIGNED asset contract.'
  }
} finally {
  Remove-Item -LiteralPath $extract -Recurse -Force
}
if (-not $SkipAttestation) {
  foreach ($asset in $expected) {
    gh attestation verify (Join-Path $root $asset) --repo $Repository | Out-Null
    if ($LASTEXITCODE -ne 0) { throw "Attestation verification failed for $asset" }
  }
}
Write-Output 'VeilSend v0.2.0-beta.1 draft assets verified.'
```

The recursive delete is limited to the literal `.portable-inspection` child whose parent was resolved from the explicit assets directory. Do not accept wildcards, environment-derived broad roots, or alternate version names.

Implement the validator core explicitly:

```js
const topLevel = ["version", "tag", "commit", "windowsVersion", "architecture", "signed", "containsSensitiveData", "fixtureHashes", "results", "completedAt"];
const bannedKey = /^(sourcePath|savedPath|filename|sourceContent|ocrText|payload|rectangles|customTerms)$/i;
const bannedValue = /(?:[A-Za-z]:\\|\\\\|api_key|token=|SG_DIAGNOSTIC_SECRET)/i;

export function assertAcceptanceRecord(record) {
  const keys = Object.keys(record).sort();
  if (keys.join("|") !== [...topLevel].sort().join("|")) throw new Error("Acceptance top-level fields differ from the contract");
  if (record.version !== "0.2.0-beta.1" || record.tag !== "v0.2.0-beta.1") throw new Error("Wrong beta identity");
  if (!/^[0-9a-f]{40}$/.test(record.commit) || record.architecture !== "x86_64") throw new Error("Invalid accepted build identity");
  if (record.signed !== false || record.containsSensitiveData !== false) throw new Error("Signing/privacy disclosure mismatch");
  if (!Number.isFinite(Date.parse(record.completedAt))) throw new Error("Invalid completion time");
  for (const name of requiredResults) if (record.results?.[name] !== "pass") throw new Error(`Acceptance step did not pass: ${name}`);
  if (Object.keys(record.results ?? {}).length !== requiredResults.length) throw new Error("Unexpected acceptance result fields");
  const visit = (value) => {
    if (typeof value === "string" && bannedValue.test(value)) throw new Error("Sensitive value in acceptance record");
    if (!value || typeof value !== "object") return;
    for (const [key, child] of Object.entries(value)) {
      if (bannedKey.test(key)) throw new Error(`Sensitive key in acceptance record: ${key}`);
      visit(child);
    }
  };
  visit(record);
}
```

Compare all three `fixtureHashes` values with the constants in the test fixture above. The CLI reads exactly the JSON path in `process.argv[2]`, invokes the validator, and exits nonzero on any mismatch. The record stores only pass/fail facts, not screenshots or copied reports.
